# Архитектура фронтенда (`edu-web`)

> Бизнес-правила (доступ, прогресс, роли, коды ошибок) — `docs/DOMAIN-SHARED.md`. Фронтенд их не вычисляет, а отображает то, что пришло от API.
> API тестов для раннера — `docs/CONTENT-FORMAT-SHARED.md`, раздел 6. План работ — `docs/ROADMAP-FRONTEND.md`.

---

## 1. Назначение и границы

`edu-web` — это публичный сайт (главная, каталог, курсы, уроки), кабинет ученика, админка и раннер, который выполняет код учеников в браузере. Все данные приходят из `edu-api` через сгенерированный Kubb клиент. Своей базы данных и бизнес-логики доступа у фронтенда нет.

## 4. Маршруты и режимы рендера

Префикс `/[locale]` (`ru` | `ky` | `en`) обязателен. Корень `/` перенаправляет на язык из куки или `Accept-Language`, по умолчанию `ru`.

| Маршрут | Рендер | Вход | Индексация |
|---|---|---|---|
| `/` , `/tracks`, `/tracks/[track]` | Сервер, `revalidate: 60`, запрос к API без куки | нет | да |
| `/courses/[course]` | Сервер, динамический: запрос с кукой, чтобы получить состояния уроков | нет | да |
| `/courses/[course]/[lesson]` | Сервер, динамический; задания — клиентские компоненты | нет | да (кроме платных непревью) |
| `/about`, `/faq`, `/terms`, `/privacy` | Статика из `content/pages` | нет | да |
| `/login`, `/register`, … | Клиентские формы | нет | нет |
| `/dashboard`, `/profile` | Сервер (layout) + клиентские данные | да | нет |
| `/admin/...` | Клиентский | REVIEWER, ADMIN | нет |

Страницы курса и урока рендерятся динамически, потому что ответ зависит от пользователя (состояния уроков, доступ к платным урокам). На нашем масштабе серверный рендер на каждый запрос недорог, а поисковики всё равно получают полный HTML. Если нагрузка вырастет, пользовательские данные можно будет вынести в отдельный клиентский запрос и вернуть кеширование.

Маршруты админки:

```
/admin                                        обзор
/admin/content                                дерево контента с матрицей переводов
/admin/content/{tracks|courses|modules|lessons|exercises}/[id]
/admin/translations/[entity]/[id]/[locale]    экран перевода
/admin/review                                 очередь «на проверке»
/admin/users, /admin/users/[id]
/admin/reports
/admin/stats
```

## 5. Слой данных

**Единый клиент.** `src/lib/api/client.ts` — это клиент, которым пользуется весь код Kubb.

- **В браузере** запросы идут на относительный `/api` с `credentials: 'include'`. В dev-режиме rewrites Next.js проксируют `/api/*` на `localhost:3000`, поэтому сайт и API всегда на одном origin.
- **На сервере** базовый адрес — `API_INTERNAL_URL`. Кука `sid` берётся через `cookies()` из `next/headers` и пробрасывается в запрос. Для кешируемых страниц используется режим без куки.
- **Ошибки.** Ответ с ошибкой превращается в `ApiError { status, code, details? }`.

**Правила:**

- Серверные компоненты вызывают функции клиента Kubb напрямую, клиентские — через хуки TanStack Query от Kubb.
- Изменяющие запросы отправляются только из браузера (мутации TanStack Query). Server Actions для обращения к API не используются.
- После мутации инвалидируются связанные запросы. После сдачи это состояние урока, прогресс курса и дашборд; после изменений в админке — соответствующие списки и дерево контента. Если мутация влияет на страницу, отрендеренную на сервере, дополнительно вызывается `router.refresh()`.
- Если нужного эндпоинта в сгенерированном клиенте нет, `fetch` вручную не пишется: в PR описывается, какой эндпоинт нужен от API.

## 6. Аутентификация на фронтенде

Сессия живёт в httpOnly-куке `sid`, JavaScript её не видит и не хранит никаких токенов. Текущий пользователь берётся из хука `useMe` (запрос `auth_me`; ответ 401 означает гостя).

- **Защищённые разделы.** Layout группы `(cabinet)` на сервере вызывает `auth_me` с кукой и при 401 перенаправляет на `/[locale]/login?next=<путь>`. Layout админки дополнительно проверяет роль `REVIEWER` или `ADMIN`, иначе показывает 404.
- **После входа** пользователь возвращается на `next`, если это относительный путь, иначе попадает в `/dashboard`.
- **Выход.** Мутация `auth_logout`, затем очистка кеша TanStack Query, `router.refresh()` и переход на главную.
- **Вход через Google** — это обычная ссылка на `/api/v1/auth/google?redirect=<путь>`.

## 7. Мультиязычность

Используется next-intl с `localePrefix: 'always'`. Строки лежат в `messages/{ru,ky,en}.json` и сгруппированы по пространствам имён: `common`, `nav`, `auth`, `catalog`, `lesson`, `exercise`, `runner`, `dashboard`, `profile`, `reports`, `admin`, `errors`, `seo`. Ключи пишутся в camelCase.

- **Откат.** Если строки нет, `getMessageFallback` берёт русскую, а в dev-режиме пишет предупреждение в консоль.
- **Ошибки API.** Каждый код из `DOMAIN.md` имеет перевод в `errors.<CODE>`. Для неизвестного кода показывается `errors.INTERNAL_ERROR`. Правила валидации из `details` переводятся ключами `errors.validation.<rule>`.
- **Множественное число** оформляется через ICU. В русском формы `one`, `few`, `many`, `other`; в кыргызском существительное после числа не меняется («5 сабак»); в английском `one`, `other`.
- **Цена** показывается как «100 сом» во всех языках, число форматируется через `useFormatter`.
- **Смена языка** переходит на тот же путь с другим префиксом. У вошедшего пользователя язык дополнительно сохраняется в профиле (`users_updateMe`).
- **Кыргызские строки** агент пишет как черновик и перечисляет их в PR, чтобы их проверил носитель языка.

## 8. Рендер контента

Модуль `lib/markdown` — единственный путь превращения Markdown в интерфейс. Конвейер: `remark-parse` → `remark-gfm` → `remark-directive` (блоки `:::note`, `:::tip`, `:::warning`) → `remark-rehype` → `rehype-sanitize` (разрешены только нужные теги и классы) → `rehype-slug` → Shiki → `hast-util-to-jsx-runtime`.

Последний шаг превращает дерево сразу в React-элементы и позволяет подставить свои компоненты: блоки-выноски, блоки кода с кнопкой «Копировать», адаптивные таблицы, картинки через `next/image`. `dangerouslySetInnerHTML` в проекте не используется.

Модуль работает на сервере (страница урока, статические страницы) и в браузере (предпросмотр в админке). В браузере Shiki загружается лениво и только с нужными языками: js, ts, json, bash, html, css.

## 9. Урок и задание

Страница урока собирается из компонентов: хлебные крошки, оглавление курса (боковая панель на десктопе, выезжающая на телефоне), плашка «Перевод готовится», текст урока, список заданий, навигация «Предыдущий / Следующий», кнопка «Сообщить о проблеме».

Задание — клиентский компонент. CodeMirror подгружается динамически (`next/dynamic`, `ssr: false`). Состояния задания:

```
редактирование ──«Проверить»──▶ выполняется ──▶ пройдено | не пройдено | ошибка синтаксиса | таймаут
      ▲                                                         │
      └───────────────── изменение кода ◀───────────────────────┘

вошедший: после «пройдено» / «не пройдено» сдача отправляется фоном (learning_submit)
          → ответ lessonCompleted → «Урок пройден! Следующий →» и обновление оглавления
гость:    после запуска плашка «Войдите, чтобы сохранить прогресс»
```

Черновик кода сохраняется в localStorage с ключом `draft:<exerciseId>`. Подсказки открываются по одной: у вошедшего каждая фиксируется через `learning_openHint`, у гостя живёт только в состоянии страницы. Кнопка «Показать решение» активна по правилу из `DOMAIN.md` (раздел 5.3, пункт 5).

## 10. Раннер

Раннер — самая чувствительная к безопасности часть фронтенда. Его инварианты:

1. **Изоляция.** Код ученика никогда не выполняется в контексте страницы сайта: нет доступа к кукам, localStorage, DOM сайта и API от имени пользователя. Базовая схема — sandboxed iframe (`srcdoc`, `sandbox="allow-scripts"`, без `allow-same-origin`) с Web Worker внутри. Окончательную схему фиксирует спайк WEB-07 в `docs/runner-spike.md`.
2. **Таймаут.** Через 3 секунды окружение уничтожается целиком, это спасает от бесконечных циклов.
3. **Чистое окружение.** Каждый запуск идёт в новом окружении, состояние между запусками не сохраняется.
4. **Один харнесс.** `features/runner/harness.js` — копия `edu-content/tools/harness.js` с комментарием об источнике и версии. Логика тестов меняется только в `edu-content`, затем копия обновляется.

Интерфейс раннера: `runExercise({ code, tests, locale }) → Promise<RunResult>`, где `RunResult` — это `{ status: 'passed' | 'failed' | 'syntaxError' | 'timeout', results, output, syntaxError? }`.

## 11. Админка

Админка работает только в браузере, рассчитана на десктоп и планшет и закрыта от индексации (`noindex`).

- **Типовой экран** — таблица (TanStack Table с серверной пагинацией) и форма (react-hook-form + zod-схема от Kubb).
- **Опасные действия** (удаление, снятие с публикации, блокировка) требуют диалога подтверждения.
- **Результат мутаций** показывается всплывающим уведомлением.
- **Экран перевода:** слева русский оригинал только для чтения, справа редактор перевода с предпросмотром, выбор статуса.
- **Редактор задания:** поля starter, solution и tests и кнопка «Прогнать эталон», которая через раннер проверяет, что решение проходит тесты.

## 12. Дизайн-система

- **Темы и цвета.** Токены — CSS-переменные shadcn/ui для светлой и тёмной темы. Цвета в компонентах задаются только через токены, без хардкода.
- **Типографика.** Основной текст 16 px на телефоне, текст урока 17–18 px на десктопе, ширина строки урока 65–75 символов. Шрифт текста обязан поддерживать ө, ү, ң; для кода — моноширинный. Шрифты подключаются через `next/font`.
- **Мобильная версия в приоритете.** Вёрстка начинается с ширины 375 px, брейкпоинты — стандартные Tailwind. Области нажатия не меньше 44 px.
- **Иконки** — lucide-react.
- **Доступность.** Семантичная разметка, подписи у полей, видимый фокус, работа с клавиатуры, контраст не ниже WCAG AA.

## 13. SEO

- **Метаданные.** Каждая публичная страница задаёт `generateMetadata`: title, description, canonical и `alternates.languages` для всех трёх языков (через хелпер в `shared/lib/seo`).
- **Карта сайта.** `sitemap.ts` строится из `catalog_getSitemap` и включает все языки.
- **robots.** `robots.ts` закрывает `/admin`, `/dashboard`, `/profile`, а также `/dev`.
- **Платные уроки** без превью получают `noindex`.

## 14. Производительность

- CodeMirror и раннер загружаются только на страницах с заданиями.
- Shiki работает на сервере; в браузере — только в админке.
- Картинки подключаются через `next/image`, шрифты — через `next/font`.
- Цель — страница урока без редактора быстро открывается на телефоне в мобильной сети. Ориентир Lighthouse (мобильный режим): Performance не ниже 85, SEO не ниже 95.

## 16. Окружение и сборка

| Переменная | Назначение |
|---|---|
| `API_INTERNAL_URL` | Адрес API для серверных запросов (в Docker: `http://api:3000`) |
| `NEXT_PUBLIC_APP_URL` | Публичный адрес сайта (canonical, hreflang, sitemap) |

Сборка идёт с `output: 'standalone'` в Docker-образ. Kubb генерирует клиент из `http://localhost:3000/api/docs-json` командой `pnpm api:gen`, а сгенерированный код коммитится в репозиторий, чтобы сборка не зависела от запущенного API.
