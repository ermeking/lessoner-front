# Роадмап `edu-web`

> План работ фронтенда. Архитектура — `docs/ARCHITECTURE-FRONTEND.md`, бизнес-правила — `docs/DOMAIN-SHARED.md`.
> Фронтенд идёт параллельно с бэкендом. Задачи без зависимости от API (WEB-01, WEB-04, WEB-07) можно делать сразу.

## Как отдавать задачу агенту

```
Ты работаешь в репозитории edu-web.
Прочитай CLAUDE.md, docs/DOMAIN-SHARED.md и docs/ARCHITECTURE-FRONTEND.md (и docs/CONTENT-FORMAT-SHARED.md, если задача касается раннера или заданий).
Выполни задачу <ID> из docs/ROADMAP-FRONTEND.md — полный текст ниже. Работай в ветке task/<ID>.
Используй скиллы из .claude/skills, когда они подходят. Перед PR выполни скилл pr-ready.

<текст задачи>
```

Одна задача — одна сессия агента и один PR. Следующая задача начинается после проверки PR по критериям «Готово, когда».

## Веха 0. Фундамент

**Цель вехи:** каркас с мультиязычностью, темами и типизированным клиентом API.

**Связь с другими репозиториями:** WEB-02 ждёт API-01.

### WEB-01 · Каркас edu-web

**Цель:** каркас фронтенда с мультиязычностью, темой и базовым макетом.

**Сделать:**
- Next.js (App Router) на pnpm, TypeScript в strict-режиме, Tailwind, инициализация shadcn/ui.
- next-intl: языки `ru`, `ky`, `en`; `localePrefix: 'always'`; язык по умолчанию `ru`; middleware перенаправляет `/` по куке или `Accept-Language`; `getMessageFallback` отдаёт русскую строку.
- Макет: шапка (логотип-заглушка, навигация, переключатель языка с сохранением текущего пути, переключатель темы, кнопка «Войти») и подвал.
- Тёмная и светлая тема (next-themes), выбор запоминается.
- Шрифты: подобрать шрифт текста с поддержкой ө, ү, ң и моноширинный шрифт для кода. Для проверки сделать страницу `/[locale]/dev/fonts`, доступную только в dev, с тестовой строкой «Өнөр, үй, таң».
- Vitest, базовая настройка Playwright, ESLint + Prettier.
- `Dockerfile` (`output: 'standalone'`), CI: lint, typecheck, test, build.

**Готово, когда:**
- [ ] `/ru`, `/ky`, `/en` открываются, `/` перенаправляет на нужный язык.
- [ ] Переключение языка сохраняет путь, тема переключается и запоминается.
- [ ] Кыргызские буквы отображаются выбранным шрифтом, без подмены системным.
- [ ] CI зелёный.

### WEB-02 · API-клиент и Kubb

**Зависит от:** WEB-01, API-01

**Цель:** типизированный доступ к API из серверных и клиентских компонентов.

**Сделать:**
- Конфигурация Kubb: `plugin-oas`, `plugin-ts`, `plugin-client` (со своим клиентом), `plugin-react-query`, `plugin-zod`. Скрипт `pnpm api:gen`, результат генерации в `src/gen`.
- `src/lib/api/client.ts`: на сервере базовый адрес — `API_INTERNAL_URL`, и в запрос пробрасывается кука из `next/headers`; в браузере запросы идут на относительный `/api` с `credentials: 'include'`.
- Ошибки `{ code, message }` превращаются в типизированный `ApiError`.
- `QueryClientProvider` и хелпер для серверных компонентов.
- В dev-режиме rewrites Next.js проксируют `/api/*` на `localhost:3000`, чтобы сайт и API были на одном origin, как в продакшне.

**Готово, когда:**
- [ ] Запрос health работает и в серверном компоненте, и через хук в клиентском.
- [ ] Ошибка API приходит как `ApiError` с полем `code`.

## Веха 3. Практика

**Цель вехи:** безопасный раннер, задания с автопроверкой, прогресс и кабинет.

**Связь с другими репозиториями:** WEB-07 можно делать сразу; WEB-08 ждёт CONTENT-01 (harness.js); WEB-09 и WEB-10 ждут API-08.

### WEB-07 · Спайк раннера

**Зависит от:** WEB-01

**Цель:** проверить схему изоляции до того, как писать настоящий раннер.

**Сделать:** прототип «sandboxed iframe (`srcdoc`, `sandbox="allow-scripts"`) + Web Worker из Blob внутри». Проверить в Chrome, Firefox и Safari на десктопе, а также в Chrome на Android и Safari на iOS:

1. код ученика не может прочитать `document.cookie` и `localStorage` сайта, а `fetch('/api/v1/auth/me')` из его кода не проходит с сессией пользователя;
2. `while (true) {}` прерывается по таймауту 3 секунды, и страница при этом не зависает;
3. `console.log` перехватывается;
4. сколько занимает холодный запуск.

Если в каком-то браузере схема не работает, предложить альтернативу.

**Результат:** `docs/runner-spike.md` с таблицей результатов по браузерам и выбранной схемой. Код прототипа можно не сохранять.

### WEB-08 · Раннер

**Зависит от:** WEB-07, CONTENT-01

**Сделать:**
- `features/runner` по схеме, выбранной в спайке.
- Копия `edu-content/tools/harness.js` с комментарием, откуда она взята и какой версии.
- Функция `runExercise({ code, tests, locale }) → Promise<RunResult>`:
  - по таймауту возвращает статус `TIMEOUT`;
  - при синтаксической ошибке возвращает номер строки;
  - каждый запуск идёт в новом окружении, состояние между запусками не утекает.
- Dev-страница `/[locale]/dev/runner`.

**Готово, когда (Playwright на dev-странице):**
- [ ] Верное решение проходит все тесты.
- [ ] Бесконечный цикл возвращает `TIMEOUT` не позже чем через 3,5 секунды, страница остаётся отзывчивой.
- [ ] Синтаксическая ошибка показывает номер строки.
- [ ] `fetch` к API из кода ученика не получает данных пользователя.

### WEB-09 · Задание в уроке

**Зависит от:** WEB-06, WEB-08, API-08

**Сделать:**
- Компонент задания:
  - условие в Markdown;
  - редактор CodeMirror 6 (JavaScript) с крупными кнопками «Проверить» и «Сбросить», удобными на телефоне;
  - панель результатов: тесты ✓/✗ с сообщениями, вывод консоли, ошибки.
- Черновик автоматически сохраняется в localStorage; «Сбросить к стартовому коду» с подтверждением.
- Подсказки открываются по одной: для вошедшего фиксируются через API, у гостя живут только в браузере.
- Кнопка «Показать решение» активна после успешной сдачи или после всех подсказок.
- **Гость** после запуска видит плашку «Войдите, чтобы сохранить прогресс».
- **Вошедший**: каждая проверка автоматически отправляется как сдача. При `LESSON_LOCKED` показывается сообщение со ссылкой на урок, который нужно завершить. После завершения урока — «Урок пройден! Следующий →».
- Кнопка «Урок прочитан» для уроков без заданий.
- Состояние (пройдено, открытые подсказки, последний код) восстанавливается из API.

**Готово, когда:**
- [ ] Playwright: вход → урок → неверное решение (сдача с `passed: false` записана) → верное решение → урок завершён → следующий урок доступен.
- [ ] Черновик переживает перезагрузку страницы.
- [ ] Всё работает на ширине 375 px.

## Веха 5. Запуск

**Цель вехи:** полировка и сквозная проверка на продакшн-окружении.

**Связь с другими репозиториями:** QA-01 ждёт INFRA-01 (бэкенд).

### WEB-13 · Статические страницы и полировка

**Зависит от:** WEB-05

**Сделать:**
- Страницы `/about`, `/faq`, `/terms`, `/privacy` из Markdown-файлов `content/pages/{locale}/*.md` через `lib/markdown`. Тексты оферты и политики предоставит владелец, пока ставятся заглушки с явной пометкой.
- Страницы 404 и ошибки, favicon, OG-картинка по умолчанию.
- Проверка всех страниц на ширине 375 px и в тёмной теме.
- Аудит: не осталось строк без ключей перевода.

### QA-01 · Сквозной сценарий

**Зависит от:** всех задач выше. Репозиторий: `edu-web`.

**Сделать:** Playwright-сценарий против развёрнутой среды:
1. гость открывает бесплатный курс, читает урок и запускает тесты;
2. регистрируется и сдаёт задание, урок засчитывается;
3. дашборд показывает прогресс;
4. после переключения на `ky` видна плашка «Перевод готовится»;
5. администратор публикует перевод, и плашка исчезает.

Сценарий запускается в CI вручную.
