# Раннер и безопасность

Раннер выполняет чужой код в браузере ученика. Ошибка здесь позволит коду из задания (или вставленному учеником коду из интернета) действовать от имени пользователя. Поэтому инварианты из `docs/ARCHITECTURE-FRONTEND.md`, раздел 10, не ослабляются ни ради удобства, ни ради скорости.

- **Изоляция.** Код ученика выполняется только в изолированном окружении раннера: sandboxed iframe без `allow-same-origin` (с Web Worker внутри — по результатам спайка). Никаких `eval`, `new Function` или `<script>` с кодом ученика в контексте страницы. Исключение — проверка синтаксиса через `new Function` без вызова результата, и только внутри окружения раннера.
- **Атрибут sandbox.** `allow-same-origin`, `allow-top-navigation`, `allow-popups` и `allow-forms` в `sandbox` не добавляются.
- **Таймаут** 3 секунды, и по нему окружение уничтожается целиком, а не «просит» код остановиться.
- **Новое окружение на каждый запуск,** никакого переиспользования между запусками.
- **Сообщения из окружения.** Родительская страница проверяет `event.source` и форму сообщения из `postMessage`. Всё, что пришло из окружения, — недоверенные данные: вывод и ошибки показываются как текст, никогда как HTML.
- **`harness.js`** — копия из `edu-content/tools/harness.js`, логика тестов меняется только там. В копии есть комментарий с источником и версией.
- **Любое изменение схемы изоляции** требует обновления e2e-тестов изоляции (попытка прочитать куку и обратиться к API из кода ученика) и отдельной пометки в PR.
