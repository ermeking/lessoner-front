# Готовность PR в edu-web

## 1. Прогони проверки

```bash
pnpm lint && pnpm typecheck && pnpm test && pnpm test:e2e
```

Если что-то падает не из-за твоих изменений, опиши это в PR, а не отключай проверку.

## 2. Посмотри глазами

Для каждого нового или изменённого экрана:

- [ ] ширина 375 px: нет горизонтальной прокрутки (кроме таблиц и кода), кнопки легко нажать;
- [ ] тёмная тема: нет белых пятен и нечитаемого текста;
- [ ] языки `ky` и `en`: длинные строки не ломают вёрстку;
- [ ] состояния загрузки, ошибки и пустое;
- [ ] клавиатура: до всех действий можно добраться Tab-ом, фокус виден.

## 3. Пройди чек-лист

**Задача**
- [ ] Выполнены все пункты «Готово, когда» из `docs/ROADMAP-FRONTEND.md`.
- [ ] Не сделано ничего сверх задачи.

**Код**
- [ ] К API — только через `src/gen`; ручного `fetch` нет; `src/gen` не правился руками.
- [ ] Мутации инвалидируют связанные запросы.
- [ ] `'use client'` только там, где нужна интерактивность.
- [ ] Нет строк в JSX; новые ключи есть во всех трёх `messages`.
- [ ] Нет `dangerouslySetInnerHTML`; Markdown — только через `lib/markdown`.
- [ ] Раннер: если задача его касалась, e2e-тесты изоляции проходят.
- [ ] Публичные страницы: метаданные, hreflang, режим рендера по архитектуре.

## 4. Опиши PR

```markdown
## <ID>: <название задачи>

### Что сделано
- …

### Принятые решения
- …

### Нужно от API
- … (эндпоинты или поля, которых не хватило; или «ничего»)

### Кыргызские строки на проверку
- `catalog.startCourse`: «Курсту баштоо»
- …

### Скриншоты
- телефон (375 px), светлая тема
- телефон, тёмная тема
- десктоп

### Как проверить руками
1. …
```

Если менялся `docs/DOMAIN-SHARED.md`, добавь строку: **«DOMAIN.md изменён — обновить копию в edu-api»**.
