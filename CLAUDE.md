# edu-web

Фронтенд образовательной платформы по программированию: публичный сайт, кабинет ученика, админка и раннер кода.
Стек: Next.js (App Router) + TypeScript + Tailwind + shadcn/ui + next-intl + TanStack Query + Kubb.

Бизнес-правила платформы (всегда в контексте):
@docs/DOMAIN-SHARED.md

## Документация

| Файл | Когда читать |
|---|---|
| `docs/ARCHITECTURE-FRONTEND.md` | Перед любой задачей: структура, маршруты и режимы рендера, слой данных, раннер |
| `docs/ROADMAP-FRONTEND.md` | Тексты задач и порядок работ |
| `docs/CONTENT-FORMAT-SHARED.md` | Задачи, связанные с раннером, заданиями и рендером уроков |

## Команды

```bash
pnpm install
pnpm dev             # сайт :3001; /api/* проксируется на API :3000 (он должен быть запущен)
pnpm api:gen         # перегенерировать клиент из http://localhost:3000/api/docs-json
pnpm lint && pnpm typecheck
pnpm test            # Vitest
pnpm test:e2e        # Playwright
```

## Главные правила

Подробные правила лежат в `.claude/rules/` и подгружаются сами при работе с соответствующими файлами. Короткая версия, которая действует всегда:

1. **Сервер по умолчанию.** Публичные страницы — серверные компоненты. `'use client'` — только там, где нужна интерактивность.
2. **API — только через сгенерированный Kubb код.** `fetch` к API вручную не пишется. Нет эндпоинта — опиши в PR, какой нужен.
3. **Изменения — только из браузера.** Мутации идут через хуки TanStack Query. Server Actions для обращения к API не используются.
4. **Правила доступа не вычисляются на фронте.** Состояния уроков и доступ приходят от API — показывай их, а не пересчитывай.
5. **Никаких строк в JSX.** Весь текст — через next-intl, новые ключи сразу во все три файла `messages`.
6. **Раннер неприкосновенен.** Код ученика выполняется только внутри `features/runner`. Инварианты изоляции не ослабляются.
7. **Markdown — только через `lib/markdown`.** `dangerouslySetInnerHTML` в проекте не используется.
8. **Мобильная версия в приоритете.** Каждый экран проверяется на ширине 375 px и в тёмной теме.
9. **`src/gen` не редактируется вручную** — только `pnpm api:gen`.
10. **Функции будущих версий не делаются**, пока их нет в задаче. Недостающее решение — самый простой вариант, записанный в PR.
11. **Язык.** Код, имена и комментарии в коде — на английском. Описание PR — на русском.

## Скиллы

| Скилл | Когда использовать |
|---|---|
| `new-page` | Новая страница или маршрут, изменение структуры страницы |
| `api-integration` | Получение данных, мутации, обработка ошибок API, формы с серверной валидацией |
| `i18n-keys` | Любой новый или изменённый текст интерфейса |
| `admin-screen` | Экраны админки: списки, формы, редакторы |
| `pr-ready` | Всегда перед созданием PR |

## Рабочий процесс

- Ветка называется `task/<ID>` (например, `task/WEB-05`), на задачу — один PR.
- Сообщения коммитов: `feat(catalog): course page`, `fix(runner): …`.
- Изменения API видны после `pnpm api:gen`; сгенерированный код коммитится вместе с задачей.
- Если меняется `docs/DOMAIN-SHARED.md`, в описании PR пишется, что копию в `edu-api` тоже нужно обновить.
